# 까꿍 (KKAKKUNG)

> 한 칸 뒤의 얼굴

고개를 기울여 한 칸씩 걷는 **1인칭 3D 미로 공포게임**. 코너를 돌면, 내가 아는 얼굴이 서 있다.

웹캠으로 머리 자세를 읽어 조작하고, 미로 속 '그것'은 **플레이어 자신의 얼굴**을 하고 있다.
브라우저에서 그대로 돌아간다 — 클라이언트는 빌드 단계가 없다.
의존성은 멀티플레이 서버가 쓰는 ws 하나뿐이고, 혼자 볼 때는 그것조차 필요 없다.

**현재 상태: 멀티플레이 술래잡기가 돌아간다.** 미로 생성·탈출구·포획·승패·제한시간이 서버에서 판정된다.
아직 없는 것: 술래가 벽을 놓는 설계 단계, 얼굴 스냅샷 전송(지금은 전원 기본 얼굴), AI 술래.

---

## 실행

```bash
node serve.js          # 혼자 볼 때는 이것만으로 충분하다
```

→ **http://localhost:5199/spike-play.html**

팀원과 같이 하려면 아래 [멀티플레이](#멀티플레이--팀원과-술래잡기) 절을 본다 (npm install 이 한 번 필요하다).

`카메라 시작` → `중립 자세 캘리브레이션`(2초, 정면 응시) → 고개로 조작.
카메라를 허용하지 않아도 **키보드만으로 플레이할 수 있다.**

| 조작 | |
|---|---|
| 고개 좌우 | 회전 |
| 상체를 앞으로 기울인 채 유지 | 계속 전진 |
| 상체를 뒤로 | 후진 |
| `WASD` / 화살표 | 키보드 조작 (얼굴 입력과 병행) |
| `H` | UI 패널 숨기기 |

> ⚠️ **5173 포트를 쓰지 말 것.** 이전 Vite 프로젝트의 서비스 워커가 그 오리진에 남아 있으면
> 페이지를 가로채 두 번 열린다. 그래서 5199로 옮겼다.

정적 서버 하나만 있으면 되므로 `python -m http.server` 등으로 대체해도 된다.
다만 `file://` 로는 열리지 않는다 — ES 모듈이 CORS에 막히고, `getUserMedia` 는 보안 컨텍스트를 요구한다.


| 문서 | |
|---|---|
| [`docs/기획서.md`](docs/기획서.md) | 무엇을 · 왜 — 게임 설계, 기술 스택 근거, 리스크, 개인정보 원칙 |
| [`docs/구현계획.md`](docs/구현계획.md) | 어떻게 — 단계별 구현 방법, 완료 기준, 실측 기록 |

## 멀티플레이 — 팀원과 술래잡기

**술래 최대 2명 + 도망자** (총 6인까지). 4인 이상이면 술래가 2명이 된다. 술래는 도망자 전원을 잡아야 하고, 도망자는 한 명이라도 탈출구로 나가면 이긴다.

```bash
npm install          # ws 1개. 이게 있어야 멀티가 켜진다
node serve.js        # "멀티플레이: 켜짐" 이 떠야 한다
```

각자 `<주소>/spike-play.html` → 왼쪽 아래 `멀티플레이` 패널에서 이름 입력 → `방 들어가기` → `시작`.

### 팀원이 다른 PC에서 들어오려면 HTTPS가 필요하다

사설 IP(`http://192.168...`)로 접속하면 **카메라가 동작하지 않는다.** `getUserMedia`가 보안
컨텍스트를 요구하는데 사설 IP는 HTTPS도 localhost도 아니기 때문이다. 터널로 https 주소를 만든다.

```bash
cloudflared tunnel --url http://localhost:5199
```

출력에 뜨는 `https://....trycloudflare.com` 주소를 팀원에게 주면 된다. 계정도 설정도 필요 없다.
페이지가 https로 열리면 클라이언트는 자동으로 `wss://`로 붙는다.

### 규칙

| 단계 | 시간 | 내용 |
|---|---|---|
| 로비 | — | 자유롭게 걸어다니며 조작을 확인할 수 있다. 시작하면 전원 시작 지점으로 돌아간다 |
| 잠입 | 10초 | 도망자만 움직인다. 술래는 묶여 있다 |
| 추격 | 5분 | 술래가 풀린다 |
| 종료 | — | 1명이라도 탈출 → 도망자 승 / 전원 포획 → 술래 승 / 시간 종료 → 생존 시 도망자 승 |

- **이동 쿨다운이 다르다** — 술래 320ms / 도망자 400ms. 같은 속도면 거리가 영원히 안 좁혀져서
  술래가 잡을 수가 없다 (시뮬레이션 결과 8/25판 → 20/25판)
- **포획은 1칸 거리에서 즉사** — 술래 둘 중 누구에게 걸려도 끝이다
- **서로는 정면 4칸 이내에 벽이 없을 때만 보인다**
- **도망자는 탈출구 위치를 모른다** — 가까워질수록 심장박동이 빨라지는 것으로만 안다
- **술래는 도망자 위치를 모른다** — 발소리가 나는 방향으로만 쫓는다. 등 뒤면 소리가 어둡다

마지막 두 줄은 UI에서 가린 게 아니라 **서버가 아예 보내지 않는다.** 클라이언트를 뜯어봐도 알 수 없다.

### 검증

```bash
node server/test.js      # 규칙 단위 — 미로·BFS·포획·승패·정보 비대칭 (360건)
node server/nettest.js   # 진짜 소켓으로 한 판 + 얼굴 중계·폐기 (44건)
```

## 기술

빌드 없이 CDN에서 직접 불러온다.

- **[Three.js](https://threejs.org/)** — 렌더링. 후처리는 블룸 + 그레인/비네트/색수차 셰이더 패스
- **[MediaPipe Face Landmarker](https://ai.google.dev/edge/mediapipe/solutions/vision/face_landmarker)** — 얼굴 랜드마크. 메인 스레드에서 20fps로 추론
- **[One Euro Filter](https://gery.casiez.net/1euro/)** — 랜드마크 지터 제거. 가만히 있을 때의 떨림과 움직일 때의 지연을 함께 잡는다
- **Web Audio API** — 소리는 **전부 실시간 합성**이다. 음원 파일이 하나도 없다

절차적 텍스처와 절차적 사운드를 쓰는 이유는 같다: 받을 게 없으니 로딩 실패도 라이선스 문제도 없고,
무엇보다 거리·방향에 따라 소리와 화면을 **실시간으로 바꿀 수 있다**.
심장박동이 빨라지는 건 재생속도가 아니라 실제 박자 간격이 좁혀지는 것이다.

## 개인정보 — 협상 불가 원칙

**얼굴은 생체인식정보이고, 개인정보보호법상 민감정보다.** 이 프로젝트는 아래를 전제로 만든다.

1. **로컬 처리** — 얼굴 인식과 텍스처 매핑은 전부 브라우저 안에서 끝난다. 서버로 보내지 않는다.
2. **저장하지 않음** — 영상도 랜드마크도 디스크에 남기지 않는다.
3. **카메라는 항상 선택** — 허용하지 않아도 키보드로 정상 플레이할 수 있다.
4. **얼굴 스냅샷 전송 (구현됨)** — `내 얼굴 등록하기` 를 눌렀을 때만 **정지 이미지 1장**이 전송된다.
   같은 방 참가자에게만 중계하고 서버는 메모리에만 들고 있으며, **방을 나가면 즉시 폐기**하고
   남은 사람들에게도 지우라고 알린다. 언제든 `등록 지우기` 로 회수할 수 있고, 실시간 영상은 보내지 않는다.
5. **화면에 명시** — "영상은 저장하거나 전송하지 않습니다" 고지를 계속 유지한다.

법적 요구이기도 하지만, **"내 얼굴을 넘겨도 괜찮다"는 신뢰가 없으면 이 게임 자체가 성립하지 않는다.**
자세한 근거는 [`docs/기획서.md`](docs/기획서.md) §7.

현재 코드는 이 원칙을 지킨다. 네트워크로 나가는 것은 두 가지뿐이다.

1. **CDN에서 라이브러리와 모델을 받아오는 요청** (jsdelivr, Google) — 나가는 데이터 없음
2. **멀티플레이 WebSocket** — 격자 좌표·바라보는 방향·역할·이름만 오간다.
   **웹캠 프레임도 랜드마크도 얼굴 텍스처도 보내지 않는다.** §4.4의 얼굴 스냅샷 전송은 아직
   미구현이며, 붙일 때는 §7-4의 동의·폐기 절차를 함께 붙인다.

> ⚠️ `cloudflared` 터널을 쓰면 그 트래픽이 **Cloudflare를 거쳐 간다.** 위 2번의 내용(좌표·이름)이
> 제3자 인프라를 통과한다는 뜻이다. 얼굴 데이터는 애초에 보내지 않으므로 §7 위반은 아니지만,
> 임시 공개 주소라 **주소를 아는 사람은 누구나 방에 들어올 수 있다.** 테스트가 끝나면 창을 닫는다.
