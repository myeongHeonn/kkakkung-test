## 시작하는 방법

```bash
npm install     # 최초 1회 — ws 1개. 없으면 멀티가 꺼진 채로 뜬다
node serve.js
```
→ **http://localhost:5199/spike-play.html**

혼자 볼 때는 `npm install` 없이도 정적 서버로 그대로 뜬다 (멀티만 꺼진다).

`카메라 시작` → `중립 자세 캘리브레이션` (2초, 정면 응시) → 고개로 조작

**조작**: 고개 좌우 = 회전 · 상체 앞으로 기울인 채 유지 = 계속 전진 · 뒤로 = 후진 · `WASD` 병행 · `H` = UI 숨기기

> ⚠️ **5173 포트를 쓰지 말 것.** 이전 Vite 프로젝트의 서비스 워커가 그 오리진에 영구 등록돼 있어
> 페이지가 두 번 열린다. 원인 규명 완료 — 그래서 5199로 옮겼다.
> 5173을 정리하려면 DevTools → Application → Service Workers → Unregister.

## 지금 바로 할 일 — 팀원과 한 판 돌려보기

### 1. 각자 준비

```powershell
git pull
npm install          # ws 1개. 이게 있어야 멀티가 켜진다
node serve.js
```

콘솔에 `멀티플레이: 켜짐` 이 떠야 한다. `꺼짐` 이면 `npm install` 을 안 한 것이다.

### 2. 호스트가 터널을 연다

팀원 PC에서 `http://<사설IP>:5199` 로 들어오면 **카메라가 죽는다.**
`getUserMedia` 는 보안 컨텍스트(HTTPS 또는 localhost)를 요구하는데 사설 IP 는 둘 다 아니다.
그래서 터널로 https 주소를 만든다.

```powershell
winget install Cloudflare.cloudflared     # 최초 1회
cloudflared tunnel --url http://localhost:5199
```

출력에 뜨는 `https://....trycloudflare.com` 을 팀원에게 준다.
계정도 설정도 필요 없고, 창을 닫으면 주소가 사라진다.
클라이언트는 페이지가 https 면 자동으로 `wss://` 로 붙으므로 따로 만질 것이 없다.

### 3. 방에 모인다

각자 `<터널주소>/spike-play.html` → 왼쪽 아래 `멀티플레이` 패널에 이름을 넣고 `방 들어가기`
→ 2명 이상 모이면 아무나 `시작`.

**최대 6명(방당).** 술래는 **3인 이하 1명 / 4인 이상 2명**. 미로는 19×19.

`공개 매칭` 은 모르는 사람과 묶이고 **얼굴 공유가 없다.** 아는 사람끼리 하려면
`방 만들기` 로 코드를 뽑아 알려준다 — 그 방에서만 얼굴이 오간다.

| 단계 | 무슨 일이 |
|---|---|
| 로비 | 자유롭게 걸어다닐 수 있다 — 워밍업. 시작하면 전원 제자리로 |
| 잠입 10초 | 도망자만 움직인다. 술래는 묶여 있다 |
| 추격 5분 | 술래가 풀린다 |
| 종료 | 도망자 1명이라도 탈출 → 도망자 승 / 전원 포획 → 술래 승 / 시간 종료 → 생존 시 도망자 승 |

**도망자**: 탈출구는 화면에 안 나온다. **심장박동이 빨라질수록 가까운 것**이다.
**술래**: 도망자 위치가 안 나온다. **발소리가 나는 방향**으로 쫓는다. 등 뒤에서 나면 소리가 어둡다.
서로는 **정면 4칸 이내에 벽이 없을 때만** 보인다.

### 성능이 안 나오는 팀원이 있으면

**아무것도 안 눌러도 알아서 내려간다.** 오른쪽 패널 `품질` 이 자동이면 프레임을 보고
2.5초마다 한 칸씩 낮춘다. 순서는 눈에 덜 띄는 것부터다:

| 단계 | 해상도 | 후처리 | 그림자 | 그림자맵 |
|---|---|---|---|---|
| 최고 | 1.25 | O | O | 768 |
| 높음 | 1.0 | O | O | 768 |
| 높음− | 1.0 | O | O | 512 |
| 중간 | 1.0 | X | O | 512 |
| 낮음 | 1.0 | X | X | 512 |
| 최저 | 0.75 | X | X | 512 |

**추론 ms 가 14를 넘으면 화질 대신 추론 주기를 먼저 줄인다** (20 → 최저 10fps).
메인 스레드가 막힌 것이라 화질을 깎아도 안 나아지기 때문이다.

여유가 15초 이상 지속되면 한 칸 되돌린다. 오르내림이 잦으면 렉보다 거슬리므로
간격을 길게 뒀고, 중간 구간(프레임 13~22ms)에서는 아무것도 건드리지 않는다.

수동으로 고정하려면 `품질` 을 `최고/중간/최저 고정` 으로 바꾼다.
어느 단계로 내려갔는지는 `품질` 필과 `튜닝값 콘솔 출력` 의 `quality` 에 찍힌다.

### 4. 보고 올 것

- 추격이 실제로 성립하는가 (시뮬레이션은 20/25판 포획이었다 — 사람은 다르다)
- 5분이 적당한가 / 19×19 미로 크기가 적당한가
- **6인 · 술래 2명 밸런스가 맞는가** — 4명 중 1명만 나가도 도망자 승이다. 그래도 유리하면 전원 탈출 조건을 검토한다
- 술래가 발소리만으로 쫓을 만한가 (§4.3 ② 검증)
- 얼굴 입력으로 추격당하는 게 감당 가능한가 (400ms 쿨다운)
- **약한 노트북에서 자동 품질이 어느 단계에서 멈추는가** — `튜닝값 콘솔 출력` 의 `quality` 값
- 미니맵이 읽을 만한 크기인가 (168px)

## 결정 대기 중인 것

### ① 추격이 성립하는가 (기획서 §4.3) — **시뮬레이션으로 답이 나옴**

`node server/test.js` 가 25판씩 돌린 결과다. 도망자는 막다른 길을 피하며 술래에게서 멀어지고,
술래는 최단경로로 쫓는다.

| 설정 | 포획 | 평균 소요 |
|---|---|---|
| 같은 속도 400/400 | **8/25** | 11.1초 |
| 차등 360/400 | **20/25** | 22.2초 |
| **A안 320/400** (현재 적용) | **20/25** | 13.0초 |

- 문서의 우려는 **사실이었다** — 같은 속도로는 3분의 1도 못 잡는다
- A안이면 추격이 성립한다
- ⚠️ **360/400 이 더 나을 수 있다.** 포획률은 같은데 추격이 1.7배 길다.
  13초는 너무 빨리 끝난다 — 사람으로 실측한 뒤 정한다
- ⚠️ 이건 **AI 도망자** 기준이다. 사람은 더 잘 도망친다. 실측이 필요하다

B안(벽 텔레포트)은 설계 단계(S4)가 생긴 뒤에 실험한다. 놓을 벽이 없으면 텔레포트할 곳도 없다.

### ⓪ 술래 선정은 순번제가 아니다

매 판 **무작위**로 뽑되 **직전 술래는 후보에서 밀린다** (§4.3 ②). 순번제가 아니라서
세 판 중 두 번 술래가 될 수도, 한 번도 안 될 수도 있다. 불만이 나오면 순번제로 바꾼다.

술래 수는 `server/rules.js` 의 `IT_COUNT` 가 정한다 — **3인 이하 1명, 4인 이상 2명**.
§4.1 원문은 술래 1명이지만 6인까지 열면서 도망자 쪽이 너무 유리해져 올렸다. 실측 후 확정한다.

### ② 점프스케어를 쓸 것인가 — **문서와 코드가 충돌한다** ⚠️

기획서 §2.3 은 **"점프스케어(갑작스러운 소음+등장)를 쓰지 않는다"** 고 못박고 있다.
공포는 "천천히 알아보게 되는 것"이어야 한다는 원칙이다.

그런데 지금 `spike-play.html` 의 **스팅어**는 조우 첫 순간에 불협 클러스터 + 서브 드롭을 터뜨린다.
정확히 §2.3 이 금지한 그것이다. 셋 중 하나를 골라야 한다.

- **A. 스팅어를 뺀다** — 문서 원칙을 지킨다. 조우는 `far → near → contact` 3단계 시각 연출로만
- **B. §2.3 을 개정한다** — 실제로 해보니 스팅어가 좋더라, 로 문서를 고친다
- **C. 절충** — 스팅어를 `contact`(1칸)에서만, 그것도 훨씬 약하게

> 플레이해 보고 정한다. 지금은 **B 상태로 방치돼 있다** — 문서를 안 고친 채 코드만 어긴 상태라
> 어느 쪽이든 결론을 문서에 반영해야 한다.
